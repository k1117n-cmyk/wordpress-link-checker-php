# PHP版リンク検査の操作説明

導入後に参照する、設定・判定・通知・ログ・停止方法の説明です。初めて利用する場合は[導入マニュアル](INSTALLATION_GUIDE.md)から進めてください。検査本体はPHP CLI、起動用スクリプトは `/bin/sh` を使います。

## 実行環境

- PHP CLI 8.4以上。サポート中で修正適用済みの版を使います。
- curl、dom（HTMLDocument）、libxml、XMLReader、intl、mbstring、zlib、pcntl、openssl。
- proc_open、proc_terminate、flock、hrtime、dns_get_record等が利用可能であること。
- PHP/cURLから使用できるCA証明書とsendmail互換コマンド。

Composerや追加のPHPパッケージは不要です。PHPの `--check` で不足を確認します。Web側のPHP設定変更や、必要機能を省く自動切替は行いません。

## 設定

`conf/linkcheck_php_example.json` をコピーしてサイトごとの設定を作ります。本書では本番用を `conf/linkcheck_php_mysite.json`、識別名を `mysite` とします。手動テスト用は別ファイル・別の識別名 `mysite-manual` を使います。

設定ファイル内の `mail` オブジェクトを編集します。次は該当部分の抜粋です。値を実際のアドレスとパスへ置き換えてください。

```json
{
  "mail": {
    "to": "CHANGE_ME@example.com",
    "from": "CHANGE_ME@example.com",
    "sendmail_path": "/usr/sbin/sendmail"
  }
}
```

`CHANGE_ME@example.com` のままでは起動しません。宛先は1件です。SMTPパスワードやAPIキーは不要です。送信元の使用可否と受信箱への到着は初回に確認します。

ファイル名は自由ですが、常に `--config` で指定してください。`site_id` は半角英数字・`-`・`_`。相対指定した設定ファイルと `output_dir` は、実行時のカレントディレクトリではなく `wordpress_link_check/` を基準に解決します。

主な設定項目は次のとおりです。未知のキー、不正な型・正規表現は起動時に拒否します。

| 項目 | 意味 |
|---|---|
| `site_url` | 収集候補に必ず加える公開ページURL。本番ではサイトのトップページ |
| `collection` | `sitemap`・`rest`・`urls` のどれか。自動切替なし |
| `sitemap_urls` | サイトマップ入口の配列。sitemap方式で空ならオリジン直下の `/wp-sitemap.xml` |
| `additional_urls` | 追加の掲載元ページ。サイトURLを基準とする相対URLも可 |
| `allowed_origins` | 追加の掲載元オリジン。`site_url` のオリジンは自動追加。http/httpsやwwwの違いは区別 |
| `allowed_path_prefixes` | 掲載元パスの先頭一致。既定は `["/"]`。例：`["/blog/"]` |
| `exclude_patterns` | 通信前に除外するURLの正規表現配列。転送先にも適用 |
| `soft_404_patterns` | 2xx本文の受信範囲と照合する正規表現配列。既定は空 |
| `check_images` | `true` ならimgのsrc/srcsetも検査。既定は `false` |
| `crawl_internal` | `true` なら許可範囲内のリンクから掲載元を追加。既定は `false` |
| `output_dir` | 結果保存先。既定は `reports/linkcheck_php` |

サイトマップは分割・gzipに対応します。REST方式は公開投稿・固定ページを収集し、総件数の変化・ID重複・途中失敗などを未完了とします。urls方式でも `additional_urls` や `crawl_internal` の設定で掲載元が増えるため、1ページテストでは[手動テスト手順](MANUAL_TEST_PROCEDURE.md)の設定を守ってください。

| 時間・件数・受信量の設定 | 既定値と意味 |
|---|---|
| `connect_timeout` / `request_timeout` | 5秒 / 20秒。接続 / DNS等を含む1要求の上限 |
| `request_interval` | 1秒。要求開始の最低間隔。1秒未満は不可 |
| `max_runtime` | 7,200秒。再確認・再試行・共有待機を含む検査時間上限 |
| `confirm_delay` | 60秒。404/410の再確認までの最低待機。60秒未満は不可 |
| `retry_delays` | `[10, 60]` 秒。一時障害の再試行待機。各下限を下げることは不可 |
| `max_pages` / `max_links` | 5,000掲載元 / 50,000リンク先URL |
| `max_redirects` | 5回 |
| `html_limit` / `link_limit` | 掲載元5,242,880 / リンク先262,144バイト |
| `sitemap_limit` | 10,485,760バイト |
| `max_sitemaps` / `max_sitemap_depth` | サイトマップ100件 / 深さ5 |

件数上限・時間切れは未完了として残ります。毎回最初から検査し、途中再開や実行をまたぐ成功キャッシュはありません。全件が上限内に完了しない状態では全件監視として運用開始せず、結果の未完了理由から範囲・上限を検討します。

`exclude_patterns` と `soft_404_patterns` は区切り記号なしのPCRE正規表現配列です。除外規則はURLをパーセントデコードした文字列に適用します。JSON内のバックスラッシュはエスケープが必要です。

## 設定確認と初回テスト

以下は本体の配置先で実行する設定チェックです。配置先とPHPパスは利用環境に置き換えてください。

```sh
cd /home/USER/wordpress_link_check
/bin/sh bin/run_linkcheck.sh --php-bin /PATH/TO/php \
  --config conf/linkcheck_php_mysite.json --check
```

`--check` は通信・メール送信・ログ等のファイル作成を行いません。チェックの成功はサイトの取得・メール受信・検査範囲の妥当性を保証しません。

手動の初回テストは別の `site_id` で1ページだけを検査します。全件の初回テストは本番設定と `--mode cron --auto-initial` を使い夜間に実行します。コマンドと合格条件は[手動テスト手順](MANUAL_TEST_PROCEDURE.md)と[導入マニュアル](INSTALLATION_GUIDE.md)を参照してください。

初回テストはリンク切れがなくても結果メールを送ります。検査完了かつ配送受付成功時に `state/php/<site_id>/initial_notice.json` を保存します。未完了でも保存可能な結果を送りますが、その実行による初回完了記録は作りません。

`--auto-initial` は、受付記録の版・`site_id`・宛先・送信元・適用設定のハッシュを照合します。有効な記録がなければ初回として実行します。検査終了コード0または1、メール配送受付成功、最終レポート・終了ログの保存成功後に、版2の受付記録を保存し、次回から通常通知に切り替えます。未完了・配送失敗・受付不明・保存失敗なら自動切替しません。

ハッシュには検査範囲・上限・通知設定・保存先など、既定値を含む有効な設定値を使います。設定ファイルの場所・JSONの空白・オブジェクトのキー順だけを変えても再テストにはなりません。配列の順序変更は設定変更として扱います。旧版の受付記録や1ページテストの異なる設定では初回を省略しません。同じ `site_id` の別設定は記録を共有するため、手動用と本番用の識別名は分けてください。

結果と要約の実行情報に `auto_initial`・`initial_test`・`initial_config_hash` を保存します。自動モードでは `auto_initial: true`、初回は `initial_test: true`、通常は `false` です。受付記録は手動で作成・書き換えません。実際のメール受信は自動判定できず、配送受付後に未着でも次回は通常通知になるため、購入者が受信箱を確認してください。

`--initial-test` は強制再テストで、その都度結果メールを送ります。`--auto-initial` は成功後に通常通知となる自動判定です。両方同時には指定できず、`--check` とも併用できません。宛先・送信元など設定を変えた場合、自動モードでは次回に再テストします。変更後も受信を確認してください。

## 通常実行と通知条件

自動初回判定を使う場合、cronの引数を変える必要はありません。初回成功後の同じコマンドは通常通知で検査します。

```sh
/bin/sh bin/run_linkcheck.sh --php-bin /PATH/TO/php \
  --config conf/linkcheck_php_mysite.json --mode cron --auto-initial
```

| 条件 | 通知 |
|---|---|
| 自動初回判定で成功記録なし、または強制 `--initial-test` | リンク切れがなくても結果メールを1通送る。検査未完了なら理由も記載 |
| 通常実行で再確認済み404/410（`broken`）あり | 結果メールを1通送る。未完了ならその旨も記載 |
| 同じ `broken` が次回も残る | 再度通知する。新規だけの通知ではない |
| 通常実行で保留・接続失敗・初回候補・未完了だけ | 送らない。保存結果とログで確認する |
| Amazon関連URLが `excluded` | 通知しない。正常性は未確認 |

Amazon関連の直接リンク・短縮リンクとそのサブドメインは、クリック集計への影響を避けるため通信前に除外します。`amazon.co.jp`、`link.amazon`、`amzn.to`、`amzn.asia` などが対象です。固定の対象一覧は `lib/php/Support.php` の `AMAZON_DOMAINS` にあります。robots.txtも取得せず、転送先でも通信前に停止します。結果は理由付きの `excluded` になります。独自の中継URL自体へのアクセスも止める場合は `exclude_patterns` に追加します。

実装にはAmazon手動確認対象があれば通知する条件と、結果の専用欄・`amazon_manual.tsv` が残っています。ただし現行の通信前除外に該当するURLは `excluded` となり、この通知の対象になりません。専用欄が0件でもAmazonリンクの正常を意味しません。

メール本文は合計100掲載箇所まで、256KiB以内です。省略件数と詳細レポートの保存先を記載します。送信処理は1回、上限30秒で、その場の自動再送はありません。受付不明は成功扱いせず、必要な通知の失敗は最終終了コード2となります。

自動・強制初回のどちらも指定しない通常実行は、従来どおり `site_id`・宛先・送信元だけで受付記録を照合します。旧記録も受け入れ、設定範囲の変更は自動検出しません。有効な受付記録がなければ、検査通信・メール送信を始めず終了コード3となります。設定照合と自動切替には `--auto-initial` を指定してください。メールが来ないことだけで正常完了とは判断しないでください。

## 掲載元ページの429と再取得

掲載元HTMLの取得時に429が返った場合は、Retry-Afterに従って待機し、同じ掲載元を最大2回再取得します（初回と合わせて最大3回）。Retry-Afterが不正またはない場合は最低60秒待ちます。有効な待機時間の指定がある場合は、その値を優先し、既存の要求間隔や共有待機も守ります。

回復したページは通常どおり解析します。429が続く場合や、403・404・5xx・通信エラーなど別の失敗へ変わった場合は取得失敗として残します。待機が実行期限に収まらない場合や中断時は再送せず未処理とし、未完了で結果を保存します。掲載元HTMLの受信打切りも成功扱いしません。

すべての再取得は `requests.jsonl` に `purpose: source` として記録します。robots・掲載元の許可範囲・公開IP・TLS・転送先の検証は再取得にも適用します。検査時間上限は待機を含み、既定値は2時間です。

この追加は掲載元HTMLの429だけが対象です。429を発生させたサーバー側の原因を解消する機能ではありません。robots判定不能による保留も自動的には解消しません。

### 外部リンク先のrobots取得失敗

外部リンク先のrobots.txtが403・接続失敗・受信打切り等で取得できない場合は、リンク先本文への要求を保留し、`pending`・理由 `robots_unknown` として保存します。掲載元・対象URL・理由は `links.tsv`、robots取得の応答・通信エラーは `requests.jsonl` で確認できます。この保留だけなら検査終了コードは1となり、ほかの処理と初回通知の配送受付が成功すれば初回完了記録を保存して通常起動へ進めます。通常時は保留だけではメールを送りません。

ここでの外部は、判定不能になった時点のURL（転送先を含む）のオリジンが `allowed_origins` に含まれないことを指します。内部リンク先のrobots判定不能、掲載元・サイトマップ・RESTの取得失敗、時間切れ、中断、件数上限、出力・必要な通知の失敗は引き続き未完了です。robotsの取得不能が解消したことや、保留したリンク先に到達できることを示す変更ではありません。

## 判定の読み方

掲載元はリンクを載せているページ、掲載箇所はページ内の個々のリンクです。同じURLが複数ページにある場合、掲載箇所数とURL数は異なります。HTTP確認対象URL数も、robots・転送・再試行を含む実HTTP要求件数とは異なります。

| 判定 | 意味 |
|---|---|
| `broken` | 再確認でも404/410。HTTP上の再確認済みリンク切れ |
| `candidate` | 初回404/410。再確認できず未完了 |
| `unreachable` | DNS・接続・タイムアウト・408・5xx等の到達失敗 |
| `pending` | 401/403/429や外部robots取得不能による保留。理由欄も確認 |
| `tls_error` / `redirect_error` | TLS異常 / 転送異常 |
| `invalid_url` / `review` | 不正・非公開接続先等 / その他の要確認応答 |
| `soft_404_suspected` | 設定した本文規則に合致。リンク切れの自動確定ではない |
| `redirected` / `recovered` | 転送後に到達可能 / 再試行で回復 |
| `unprocessed` / `excluded` | 未処理 / 除外規則・robots・未対応形式等で対象外 |
| `ok` | HTTP上で到達可能 |

結果はHTTP応答に基づきます。`ok` や200は内容の正常性を保証せず、接続エラーも直ちにリンク切れを意味しません。`sources.tsv` の取得失敗・未処理と、リンク先の判定を分けて確認します。

ログイン、JavaScript実行、ページ内アンカーの存在確認、本文の自動修正は行いません。管理・認証・カート等の操作用URLは既定で除外し、サイト固有の操作URLは除外規則で指定します。robots.txtを確認し、WAF・CAPTCHAを回避しません。接続は公開IPの80/443に限定し、TLS証明書を検証します。

## 表示と中断

対話実行では通信・DNS・再確認の待機中も約1秒ごとに `#` を表示します。60文字ごとに改行します。件数や進捗率を示す表示ではありません。

`--progress hash` で明示的に表示、`--progress none` で抑止できます。`--mode cron` は常に抑止します。Ctrl+CまたはSIGTERMでは可能な範囲で結果を保存し、終了コード2になります。OSによる強制終了等では完全な保存は保証できません。

## 保存先・終了コード

```text
reports/linkcheck_php/<site_id>/<実行日時_一意ID>/
  summary.md        要約・判定件数・検査と通知の成否・適用設定
  links.tsv         全掲載箇所、掲載元、リンク先、HTTP判定原記録
  amazon_manual.tsv Amazon手動確認対象の全掲載箇所（同じ列構成）
  sources.tsv       掲載元の取得状態・除外や失敗の理由
  requests.jsonl    GET単位の日時・応答・転送・再試行。本文は保存しない
  status.json       実行中／完了／未完了／結果不明の機械可読記録
logs/php/<site_id>/  PHP実行ログとシェルの起動ログ
logs/php/startup/    site_idを確定できない起動失敗
state/php/<site_id>/ 初回通知の受付記録
state/php/shared_http/ 全サイト共通の接続先別要求間隔・429待機記録
```

終了コードは0＝予定範囲完了・問題なし、1＝予定範囲完了・要確認あり、2＝検査または必要な通知が未完了、3＝設定・環境不正／初回未実施／重複起動。通知条件はコード1そのものではなく、Amazon以外の `broken` またはAmazon手動確認対象の存在です。要約の通常判定件数からAmazon手動確認対象を除き、専用の件数・一覧に分けます。転送のみ・回復のみは0となります。

起動ログは `launcher.*`、PHP実行ログは実行ID付きの `.log` です。検査・メール送信の結果はPHPログとsummaryに記録します。対話モードのPHP出力は端末、cronモードのPHP出力は起動ログへ記録します。開始記録しかない実行は正常と判断せず、statusとプロセスの状態を確認してください。

新規ファイルは0600、ディレクトリは0700を基本とし、既存の権限を一括変更しません。URLにはクエリ情報が残るため、レポートはWeb公開領域の外へ保存します。終了済みのログ・レポートは、下記の保存期間に従って自動削除します。

TSVはUTF-8・タブ区切りで、CSVの引用規則を使います。フィールド内のバックスラッシュ・タブ・改行はエスケープされます。表計算ソフトで開く際は区切りと文字コードを指定してください。要約と保存日時は日本時間（+09:00）で、cronのタイムゾーンとは別です。

## エラー・未着・未完了の確認先

| 状況 | 確認する場所と対応 |
|---|---|
| 設定チェックが失敗 | 端末のエラー表示。`--check` はログを作らない。該当の設定・環境を直して再チェック |
| 通常起動で終了コード3 | 端末・`logs/php/startup/`・対象の `launcher.*`。設定、PHP、初回記録、重複起動を確認 |
| 終了コード2 | 同じ実行IDの要約の未完了理由、`status.json` の `scan_code`・`exit_code`・`mail`、実行ログ |
| メールが来ない | 同じ実行の `mail.state` と `reason`。`not_sent` は条件による無送信、`failed` は失敗、`unknown` は受付不明 |
| `accepted` だが未着 | 宛先・迷惑メールを確認。送信元の利用条件やサーバーの配送記録を確認。配送受付と受信は別 |
| 結果がない／開始記録のみ | `launcher.*` と `logs/php/startup/`、cronの時刻・絶対パス。実行中か不明のまま再起動しない |

`summary.md` の「状態」は検査自体の状態です。通知失敗で最終終了コード2になることもあるため、検査終了コードと最終終了コードを分けて確認してください。自動モードの初回失敗は、原因を直せば次回のcronでも初回を実施します。失敗が続く場合はcronを一時停止して原因を確認します。強制再テストでの再実行も実通信・メール送信を伴います。

## 複数サイトの個別実行と要求間隔の共有

本体は1か所に配置し、サイトごとに設定ファイルとcronを分けます。`site_id` はサイトごとに異なる値にしてください。各サイトは別プロセスで並行実行でき、レポート・ログ・通知・初回テストの記録はサイト別です。一括実行機能は追加していません。

次は通常起動の例です。各設定ファイルを作成し、サイトごとに手動テストと夜間の全件初回テスト・受信確認を済ませてから、通常運用へ切り替えます。

```sh
/bin/sh bin/run_linkcheck.sh --php-bin /PATH/TO/php --config conf/linkcheck_php_mysite.json --mode cron --auto-initial
/bin/sh bin/run_linkcheck.sh --php-bin /PATH/TO/php --config conf/linkcheck_php_site2.json --mode cron --auto-initial
```

`site2` の設定は例示であり、作成済みではありません。

同じ本体から起動した全サイトは、`state/php/shared_http/` の記録で接続先ごとの要求開始間隔を共有します。接続先は通信方式・ホスト名・ポートの組み合わせです。全HTTP/HTTPS要求に適用しますが、Amazon等の通信前除外には要求を送りません。サイトマップ・REST API・掲載元・robots.txt・リンク先・転送・再試行にも適用されます。

- 各プロセスの既存の待機を守ったうえで、要求直前に共通記録を確認します。同じ接続先への要求開始は全プロセス合計で最低1秒間隔です。
- 直前の要求と今回の要求で設定間隔が異なる場合は、大きい方の間隔を空けます。robotsの待機も共有に反映します。
- 429のRetry-Afterを共通の待機期限に反映します。不正・欠落時は最低60秒。待機後に記録を再確認するため、他プロセスによる待機延長も反映します。すでに開始した要求を取り消すことはありません。
- ファイルロックは記録の確認・更新の間だけ保持します。通信完了まで保持するものではなく、同時接続数を全プロセス合計1件に制限する機能ではありません。
- 他の接続先のプロセスは進められますが、待機中のプロセス自身はその要求の順番を待ちます。待機とロック待ちは設定した検査時間上限（既定2時間）に含まれ、中断と進捗表示にも対応します。
- 記録やロックの読み書きに失敗した場合は、共有制御を省略せず検査未完了として保存します。強制終了で残ったロックファイルは削除せず利用します。ロックの有効性をファイルの存在だけでは判断しません。

共有ファイルは接続先のハッシュ名を使い、ロック用 `.lock` と時刻記録用 `.json` に分けます。時刻記録はロック中に一時ファイルから置換します。共有時刻は再起動後も解釈できるシステム日時、実際の待機と実行期限は単調増加時計で管理します。新規ファイル0600・ディレクトリ0700を基本とし、実行中に共有記録やロックファイルを削除しないでください。

要求履歴には共有待機の秒数 `shared_wait_seconds`、実行情報には共有記録の保存先を残します。共有待機秒数はプロセス内の通常待機を含みません。実行終了後も、他サイトが使う待機期限は残します。

共有範囲は同じサーバー・実行ユーザー・本体の配置です。別配置・別サーバー・別の検査ツールとは共有しません。サイト数に応じたCPU・メモリ負荷の制御は別であり、5サイト・10サイトの同時稼働は未検証です。cronの開始時刻は実測した所要時間と負荷に合わせて決めます。

## 定期実行と停止

次は初回から通常運用まで同じ行で使う、毎日03:00の自動初回判定の登録例です。絶対パスを利用環境に置き換え、時刻はサーバーのcronのタイムゾーンで確認します。

```cron
0 3 * * * /bin/sh /home/USER/wordpress_link_check/bin/run_linkcheck.sh --php-bin /PATH/TO/php --config /home/USER/wordpress_link_check/conf/linkcheck_php_mysite.json --mode cron --auto-initial
```

`--mode cron` は稼働表示を抑止し、PHP出力を起動ログに残します。cronへの登録機能はありません。`--auto-initial` は残したままにし、初回用・通常用を二重登録せず、既存のジョブや共通設定は残してください。旧来の `--initial-test` 付きcronを自動切替へ移行する場合は、その引数を `--auto-initial` に置き換えます。新版を配置しただけではcronの引数は変わりません。登録・初回確認・切替の順序は[導入マニュアル](INSTALLATION_GUIDE.md)に従います。

今後の起動を止めるには対象のcronジョブを無効にします。既に実行中の検査は、それだけでは停止しません。対話実行ならCtrl+C、別端末からは実行ユーザーとコマンドを照合した対象プロセスへSIGTERMを送ります。起動シェルは子PHPへシグナルを転送します。PIDを特定できない場合は一括終了を行わず、サーバーのプロセス確認方法に従ってください。

停止後は起動ログの終了記録と結果の状態を確認します。強制終了などで保存できなかった記録は、正常完了と判断しません。実行中に配置先を削除・上書きしたり、ロックファイルを削除したりしないでください。

## 保存期間と自動削除

保存期間は30日です。検査開始時にサイトのロックと初回起動条件を確認した後、そのサイトの終了済みログ・レポートを整理します。30日ちょうどの記録は残し、終了から30日を過ぎ、ファイルの最終更新も30日より前のものを削除します。設定ファイルの追加編集や削除用cronの登録は不要です。`--check`・設定情報の表示・起動条件不成立時には削除しません。

| 対象 | 削除条件 |
|---|---|
| `output_dir/<site_id>/<実行ID>/` | `status.json` の識別子がディレクトリ名と一致し、終了日時付きの `complete` または `incomplete`。既知のレポートファイルだけが入っていること |
| `logs/php/<site_id>/<実行ID>.log` | 末尾に日時付きの `finish` または `failure` 記録があること |
| `logs/php/<site_id>/launcher.*` | 末尾に日時と終了コード付きの `finish=` 記録があること |

実行中・終了不明・壊れた状態記録・終了記録のないログは残します。別用途のファイルやサブディレクトリを追加したレポート、シンボリックリンクを含むレポート、シンボリックリンク経由の保存先も削除しません。サイトを特定できない `logs/php/startup/` は対象外です。他サイトの記録・設定・初回受付と共有待機に使う `state/`・ロックファイルも削除しません。

削除件数と警告は今回のPHP実行ログの `retention` 記録と `status.json` の `retention` に残します。削除できない場合は警告を出し、検査を続けます。保存先の安全確認で見送った場合や、終了不明の記録が増えている場合は、その警告と該当する実行を確認してください。

検査を停止している間は削除しません。次にそのサイトを起動したときに対象を整理するため、常に30日分だけになる保証やディスク容量の上限管理ではありません。長く残したい結果は、期限前に別の場所へコピーしてください。`state/` は容量整理のために削除しないでください。
