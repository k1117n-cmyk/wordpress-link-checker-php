# PHP版スクリプトの手動テスト手順

手動テストは、サーバー上で公開ページ1ページだけを掲載元として検査し、結果保存とメール受信を確認します。サイトマップを使った全件検査は、後の夜間テストで行います。

## 1. 手動テスト専用の設定を作る

[導入マニュアル](INSTALLATION_GUIDE.md)の配置・本番用設定・設定チェックを済ませてから進めます。次の配置先とPHPパスは利用環境に置き換えてください。

```sh
cd /home/USER/wordpress_link_check
cp conf/linkcheck_php_mysite.json conf/linkcheck_php_manual.json
```

コピー先の `conf/linkcheck_php_manual.json` をエディターで開き、次の項目を変更します。本番用ファイルは書き換えません。

| 項目 | 手動用の設定値 |
|---|---|
| `site_id` | `"mysite-manual"`。本番の `"mysite"` と必ず分ける |
| `site_url` | 自分のサイト内の、検査する公開ページ1件のURL |
| `collection` | `"urls"` |
| `sitemap_urls` | `[]` |
| `additional_urls` | `[]` |
| `crawl_internal` | `false` |
| `check_images` | `false` |
| `mail` | 本番用からコピーした実際の宛先・送信元・sendmailパス |

その他は設定例の値を維持します。JSONにはコメントや末尾の余分なカンマを入れません。

掲載元は `site_url` の1ページだけです。そのページ内のリンク先にもアクセスしますが、リンク先から掲載元を追加収集することはありません。リンクの少ない公開ページを選んでください。`max_pages: 1` で全件検査を打ち切る方法は使いません。

初回受付記録は `site_id` ごとに保存されます。ファイル名だけを分けて同じ識別名を使うと、自動判定なしの通常起動では、この1ページの完了記録で本番の起動も許可してしまいます。

## 2. 実行前の設定を照合する

本番用と手動用の実ファイルを開き、次を確認します。

- 本番用は `conf/linkcheck_php_mysite.json`、識別名は `mysite`、収集方式は `sitemap` で、実際のサイトマップが設定されている。
- 手動用は `conf/linkcheck_php_manual.json`、識別名は `mysite-manual` で、手順1の全項目と一致する。
- 実行コマンドの `--config` は手動用ファイルを指している。

照合後に設定と環境をチェックします。

```sh
/bin/sh bin/run_linkcheck.sh \
  --php-bin /PATH/TO/php \
  --config conf/linkcheck_php_manual.json \
  --check
```

「設定・実行環境は有効です（通信・送信・ファイル作成なし）」と表示され、終了コード0なら次へ進みます。このチェックは、1ページ限定や本番との識別名の違いを自動判定するものではありません。

## 3. 手動で検査とメール送信を行う

```sh
/bin/sh bin/run_linkcheck.sh \
  --php-bin /PATH/TO/php \
  --config conf/linkcheck_php_manual.json \
  --initial-test
```

実サイトへのアクセス・結果保存・結果メールの送信を行います。リンク切れがなくても初回結果を送ります。1ページでも、リンク数や再確認の待機によって数分以上かかる場合があります。表示される `#` は稼働表示で、進捗率ではありません。

終了時には結果保存先とメール情報を表示します。終了直後に次を実行すると、終了コードを確認できます。

```sh
echo $?
```

## 4. 同じ実行の結果で合格条件を確認する

既定では次の場所に結果とログを保存します。

```text
reports/linkcheck_php/mysite-manual/<実行ID>/
logs/php/mysite-manual/launcher.*
logs/php/mysite-manual/<実行ID>.log
```

| 確認対象 | 合格条件 |
|---|---|
| 設定ファイル | 今回の起動ログ `launcher.*` の `config=` が手動用ファイルを指す |
| 識別名 | 保存先と `summary.md` の「適用設定」の `site_id` が `mysite-manual`。本番の `mysite` と異なる |
| 検査範囲 | 適用設定が手順1と一致し、`sources.tsv` が指定した1ページのみ、`state` が `ok` |
| 検査結果 | 要約の検査・最終終了コードが0または1、「未完了の理由」が「なし」 |
| 結果保存 | `summary.md`・`links.tsv`・`sources.tsv`・`requests.jsonl`・`status.json`・`amazon_manual.tsv` が保存されている |
| メール配送受付 | 要約の「メール・実行情報」または `status.json` の `mail.state` が `accepted` |
| メール受信 | 指定の受信箱に届き、実行ID・サイト・件数が結果と一致し、日本語が読める |

終了コード1でも、検査が完了していれば動作確認としては合格にできます。リンク先すべての正常を意味しません。設定の不一致があれば、検査と受信が成功しても手順どおりの合格とはしません。

設定不一致は修正してから、設定チェックと手動テストをやり直します。`--initial-test` を再指定するだけでは不一致は解消しません。本番と同じ識別名で実行した履歴があっても、その受付記録を全件完了の証拠にせず、本番は別途夜間の全件初回テストで確認します。`--auto-initial` は適用設定も照合するため、1ページ用の記録や旧版の記録では本番の初回確認を省略しません。受付記録を手動で作成・書き換える必要はありません。

## 5. 不合格の場合と本番テストへの移行

終了コード2・3、メール受付失敗、未着の場合は先へ進みません。設定エラーは端末表示と `logs/php/startup/`、検査中・未完了は今回の `status.json` と実行ログを確認します。`--check` のエラーはログを作らないため端末表示を確認してください。

`accepted` は配送受付です。未着なら宛先・迷惑メールフォルダーを確認し、配送受付後の確認方法は[導入マニュアルの未着時の手順](INSTALLATION_GUIDE.md#メールが届かない場合)に従います。実行中か不明のまま繰り返し起動しないでください。

すべての合格条件を満たしたら、[導入マニュアルの夜間全件初回テスト](INSTALLATION_GUIDE.md#6-夜間に全件検査を自動初回判定で起動する)へ進みます。cronには本番用設定と `--auto-initial` を登録し、手動テスト用設定は登録しません。手動の `--initial-test` は毎回通知する強制テストで、自動切替用の引数とは異なります。
